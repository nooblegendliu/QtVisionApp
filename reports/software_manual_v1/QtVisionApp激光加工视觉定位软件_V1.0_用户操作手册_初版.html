1 软件概述

软件用于激光加工设备的视觉定位与标定：接收上位机命令，按定位模式控制相机和照明，采集灰度图像，计算 X、Y、R，反馈定位判定，并提供配置、监控和诊断。软件与上位机或激光打标软件协同；本程序不承担激光轨迹规划、激光器底层控制、运动控制或生产调度。

功能使用入口与作用
运行监控查看当前应用、视觉、通信、任务状态及最新结果；浏览单图或四图。
视觉配置相机序列号、曝光与增益、触发、光源亮度、算法主配置选择与校验。
相机校正中心相机与四角相机的理论点、圆心检测、坐标变换计算和质量验证。
通信与系统TCP、结果确认、日志容量与级别、运行后端和配置修订信息。
诊断日志查看运行消息、错误与配置过程，清空当前显示。
服务与视图菜单重试初始化、重试 TCP、恢复视觉服务、切换独立监控。
文件功能应用 JSON、算法 YAML、角色标定文件、Mark 模板与理论点文件。

两种定位方式

Edge 使用 Center 中心相机单图，对四边进行识别、几何计算和标定转换。MarkPoint 使用 TopLeft、TopRight、BottomRight、BottomLeft 四台角相机，在每台图像中识别 Mark 点，再转换到统一坐标系形成位姿。生产定位统一由 TCP 发起，界面不提供本地生产定位按钮。

3 部署、启动与首次检查

  1. 保留现有部署目录结构：x64/Release 放置程序及运行依赖，config 放置应用配置，VisionAlgorithm/config 放置算法和标定配置；Mark 模型按参数文件所引用路径提供。
  2. 复制 config/vision_app.example.json 作为设备配置，填写五台相机序列号、光源控制器序列号、实际输出通道、监听地址与端口，核对算法路径。REPLACE_* 是待替换标记，不能直接当作设备参数。
  3. 安装与程序匹配的海康运行环境和设备驱动，确认相机与工控机网络、外部触发接线、光源连接及供电。真实设备型号、角色与序列号一一对应。
  4. 在项目根目录打开终端，用以下命令启动；也可创建包含相同参数和工作目录的快捷方式。
  5. 观察应用与视觉状态。视觉初始化完成后软件开始 TCP 监听；出现初始化错误时，根据诊断检查配置和设备后点击“重试初始化”。

真实硬件启动

.\x64\Release\VisionApp.exe --config .\config\vision_app.example.json --backend hik

无硬件演示启动

.\x64\Release\VisionApp.exe --config .\config\vision_app.simulation.example.json --backend simulation

省略 --backend 时使用 hik。simulation 还要求应用 JSON 中 simulation.enabled=true，不会因真实硬件启动失败自动切换到模拟。--config 为必需参数，--help 显示命令帮助，--version 显示程序版本。当前 main.cpp 不支持 --mode 参数。

本次截图使用应用示例的独立副本，将端口改为 19090、日志改到文档工作目录，避免修改原有设备配置。若沿用仓库示例，默认端口为 9000。缺少依赖 DLL、平台插件或有效配置时，应先修复部署问题再启动。

4 主界面与状态阅读

  1. 启动程序进入详细窗口，首先查看顶部“运行状态”。
  2. 通过“运行监控、视觉配置、相机校正、通信与系统、诊断日志”标签切换功能。
  3. 在配置页使用底部“撤销修改”和“应用并保存”；在监控或校正页底部显示相应业务操作。
状态区域阅读方式
应用 / 视觉分别表示程序整体状态和视觉服务状态；应用启动不等于视觉可接受任务。
TCP“监听中”表示等待连接；“已连接（代次…）”表示有客户端；网络连接不等于视觉就绪。
任务 / 任务ID查看空闲、准备、执行、等待确认等状态，任务ID用于关联本次上位机命令。
最新定位结果显示最近完成任务的ID、模式、完成时间、判定和坐标；恢复服务不会自动生成新定位结果。

5 相机与触发配置

  1. 从主窗口点击“视觉配置”，选择“相机”。
  2. 按角色填写相机序列号，设置曝光、增益及采集触发参数。角色和型号在表格中作为固定识别信息显示。
  3. 确认任务空闲后点击“应用并保存”，按确认框继续；查看配置修订与运行状态。
参数示例值 / 含义
角色与型号Center → MV-CH250-90GM；四角 → MV-CS120-10GM。序列号必须正确、非空且按角色独立绑定。
曝光 / 增益曝光示例 10000 μs，增益 0；曝光须为正，增益单位沿用设备 Gain 节点。实际可用范围由设备决定。
采集超时示例 1000 ms；等待硬件采图的有限时间，与算法执行预算分开。
输入线 / 边沿LINE0 或 LINE2；RISING_EDGE 或 FALLING_EDGE，与上位机接线和信号一致。
触发延迟示例 0 μs，非负；按实际触发时序配置。

界面曝光范围为 0.001～10000000 μs，增益输入范围为 -1000～1000；这些是编辑控件范围，不代表每台相机支持该全部范围。生产硬触发收到 locatePrepared 后，由外部系统提供约定触发信号。

6 光源配置

  1. 在“视觉配置”下点击“光源”。
  2. 填写光源控制器序列号，按 WhiteBacklight、CoaxialRed、CoaxialGreen、CoaxialBlue 绑定物理输出选择值。
  3. 设置各通道归一化亮度，确认设备与通道对应关系后应用并保存。
项目说明
WhiteBacklight白色背光，供 Edge 采集使用。
CoaxialRed / Green / Blue同轴红、绿、蓝通道，供 MarkPoint 模式照明使用。
outputSelector控制器真实输出选择名称；示例 SIM_*、REPLACE_* 不代表实物通道。四通道映射需独立且有效。
normalizedIntensity范围 0.0～1.0，示例 0.5；适配器映射到设备支持的实际亮度范围。

光源参数通过空闲时受控应用生效。定位采集过程按模式控制照明并进行关灯清理；本界面没有独立手动开灯、脉冲时间编辑或光源 TCP 控制功能。控制器或通道不支持必需节点时，检查配置及诊断信息。

7 算法配置文件选择与校验

  1. 在“视觉配置”下点击“算法”，查看当前主配置路径。
  2. 点击“浏览”选择算法 YAML 主配置文件，或直接编辑路径。
  3. 点击“重新校验”，等待校验状态更新。路径、参数、标定或模型缺失时修正对应资源后重试。
  4. 需要切换当前运行配置时，点击“应用并保存”；仅校验通过不等于新配置已经投入运行。

截图中的“Edge/Mark 配置及引用资源校验通过”是统一界面文案。实际加载取决于 enabled_algorithms 开关：当前示例仅启用 Edge，因此这条文案不表示已经完成真实 MarkPoint 模板识别验收。

配置维护原则

主配置通过相对路径引用参数与标定文件；相对路径以拥有该引用的文件所在目录为基准。应用 JSON 的 algorithmConfigPath 则相对于应用 JSON 所在目录解析。配置必须整体兼容，不能只移动主文件而遗漏依赖文件。

若只修改了同一路径下的 YAML 内容，不能把“重新校验”当作运行时重新加载。建议维护人员准备完整的新配置目录并在界面切换路径，或安全退出后重新启动，使修改确定生效。

8 定位操作与结果解释

  1. 确认应用和视觉均就绪、任务空闲；需要的算法已启用，标定维护已结束。
  2. 上位机建立 TCP 长连接并保持心跳，发送带 taskId 和 mode 的 prepareLocate。
  3. 真实硬件等待准备通知后，按外部设备协议触发目标相机采集。软件执行照明、采图与定位。
  4. 在“运行监控”查看结果；上位机收到最终结果后发送同 taskId 的 resultAck。
结果含义与后续操作
OK算法输出有效且 X/Y/R 有限；只有 OK 坐标可进入设备动作或打标流程。
NG正常完成但目标/几何/质量条件不满足。最终 X=Y=R=0.0 为占位，不是有效零位。检查工件、图像与参数。
ERROR硬件、算法、配置或内部执行失败。网络只发送稳定错误码和说明，不发送坐标；按错误原因处理。
Busy已有任务、结果交付或维护流程占用。新定位不排队，应在空闲后重新发起；状态查询仍可用。

X、Y、R 的当前计算约定

当前生产算法将图像点转换为物理点，X/Y 为四个物理角点或 Mark 点的平均中心坐标。R 使用左右中点连线相对物理 +X 轴的 atan2 角度，单位为度，归一化到 [-90°,90°)。物理轴方向和原点由标定定义；该输出不是自动减去某个示教中心的补偿量。

正确以毫米理论点建立标定后，X/Y 使用毫米。随库示例标定包含单位矩阵占位，未经实际标定的数值不能解释为设备毫米坐标。界面通常以三位小数显示，通信传输使用 double 数值。

8.1 Edge 抓边定位示例

入口为“运行监控”。上位机使用 mode="EDGE" 发起任务；真实模式需保证中心相机、白色背光、抓边 ROI 和中心标定可用。

  1. 查看右侧“定位模式”为 Edge，任务ID与上位机记录一致。
  2. 查看判定为 OK，示例显示 X=12.500、Y=-3.200、R=1.250，错误信息为“无”。
  3. 通过图像区查看 Center 图像；滚轮缩放、拖动平移、双击恢复适应窗口。
  4. 客户端确认结果后任务回到空闲，可接受下一次定位。

本图的灰色图像和坐标来自模拟配置，不是四边检测截图。真实算法会执行图像校正、四边卡尺采样、直线拟合、角点及物理位姿计算；检测不足或质量不合格时可得到 NG。

8.2 MarkPoint 抓点定位示例

上位机使用 mode="MARK_POINT" 发起任务。真实运行要求四角相机齐备、四套标定处于统一物理坐标系、Mark 模板和各角色 ROI 有效，并启用 mark 算法。

  1. 确认四图分别标为 TopLeft、TopRight、BottomLeft、BottomRight；角色表示相机位置，不是同一幅图中的四个区域。
  2. 查看右侧模式、任务ID及最终判定。图中 NG 的三个坐标均为 0.000。
  3. NG 时检查目标可见性、光照、ROI、模板及质量阈值；错误结果则根据错误码排查。
  4. 向服务端确认最终 NG 结果，确认完成后再发起下一任务。

四角采集作为一次完整任务处理，缺少任一路不能用其余图像代替成功。模拟后端可以演示 MarkPoint 协议与四图展示，但不检查生产模板匹配效果。

8.3 定位故障与服务恢复

  1. 记录任务ID、错误提示、发生时间，并在“诊断日志”查看相关消息。
  2. 检查相机、光源、触发信号或配置问题；需要维护时先停止上位机继续发起任务。
  3. 任务结束且恢复入口可用时，点击顶部“恢复视觉服务”，或菜单“服务 → 恢复视觉服务”。
  4. 等待视觉状态恢复就绪，然后由上位机重新发起新的定位任务。最近一次错误记录可继续保留，直至新任务结果替换。

图中 HARDWARE_FAILURE 来自 simulation.failFirstCapture=true 的一次性故障注入。本次实际执行恢复后，下一 Edge 任务返回 OK。恢复不会重新执行失败任务，也不会将旧错误改成成功。

“重试初始化”用于初始化失败后的重建；“重试 TCP”用于网络监听失败；“恢复视觉服务”用于已建立运行时发生业务故障后的恢复。应根据当前状态使用对应入口。

9 独立监控窗口

  1. 在详细窗口顶部点击“打开独立监控”，或选择“视图 → 打开独立监控窗口”。
  2. 软件显示独立监控窗口并隐藏详细窗口；根据最近任务模式显示中心单图或四角四图。
  3. 点击右上角“返回详细模式”恢复详细窗口，查看完整坐标、配置和诊断。

监控窗口用于集中观察图像，图中的单色块来自模拟相机。滚轮缩放、拖动平移、双击恢复适应。切换显示窗口不会改变 TCP 任务准入、定位模式或相机触发。

本窗口未设置生产定位按钮，也不单独显示详细窗口中的完整状态和坐标表。关闭窗口会进入应用退出流程；要继续运行并查看配置，应使用“返回详细模式”。

10 中心相机校正入口

  1. 确保生产定位停止且软件空闲，进入“相机校正 → 中心相机校正”。
  2. 检查页面后端提示和当前步骤；点击底部“选择理论点”，选择 UTF-8 两列 X,Y 文件。
  3. 选择文件后检查路径、内容校验和点数；只有满足前置条件的后续按钮才可用。

左侧为图像和圆心覆盖层，右侧为理论点来源、点位对应、候选矩阵及质量指标。右侧内容超出可视区域时可滚动；拖动中间分隔条调整宽度，点击“隐藏数据”扩大图像区，再点击“显示数据”恢复。

本次仅展示真实界面入口，未使用真实标定板完成结果求解。软件页面负责图像到加工平面映射，外部激光标定点由外部系统生成。现有相机内参、畸变及新内参仍需通过相应资源文件提供。

10.1 中心校正完整操作步骤

顺序操作观察与判断
1选择理论点以理论点文件行顺序定义 P1～PN，确认点数与配置的 n×n 网格相同。
2采集图像点击“采集图像”；取得维护锁后采集中心相机图像。检查标定网格是否完整、清晰、无明显遮挡。
3检测圆心点击“检测圆心”，检查圆心覆盖层；未检出完整点集时调整图像或检测参数后重试。
4指定 P1、P2在图中依次点击已检测的圆心。P1 是物理编号起点、须为网格角点；P2 是沿物理 +X 的直接相邻点。
5计算矩阵点击“计算矩阵”，检查点表中的像素 U/V 与实际 X/Y 对应及 3×3 候选 image_to_physical。
6质量验证点击“质量验证”，核对采用点数、RMS 和最大误差；只有质量通过才进入应用。
7应用候选点击“应用候选”，保存该角色标定并重新建立运行时；成功后确认视觉就绪。
8重置放弃当前流程时点击“重置”，清空页面会话结果并释放维护占用；重置不是恢复已应用的历史标定。

图像与质量指标

“适应窗口”按比例显示完整图像，“1:1”按原始像素显示；滚轮缩放、拖动平移、双击恢复适应。点表中的“是否采用”表示是否参与鲁棒拟合；RMS 和最大误差按全部理论对应点统计，包含未被拟合采用的点。

参数示例为 5×5 共25点，至少采用24点，RMS≤0.03 mm，最大残差≤0.08 mm；这些是随库示例阈值，不能视为真实设备已达到的精度。

采集开始后到应用成功或重置前，生产定位及部分维护操作返回 Busy。质量不通过属于候选不合格，应重新检查对应关系、图像和参数；不要将失败候选用于生产。

11 四角相机校正入口

  1. 进入“相机校正 → 四角相机校正”。
  2. 在右侧分别为 TopLeft、TopRight、BottomRight、BottomLeft 点击“选择”，绑定对应角色理论点文件。
  3. 检查四文件点数一致并使用同一设备加工平面坐标系，再进入后续步骤。

本次切换到该页面时，实际程序提示“后端未接入：仅文件选择与界面预览可用”，后续计算按钮禁用。因此本节提供入口与当前代码中的完整流程说明，不宣称本次已执行四路标定。应以实际后端提示和按钮可用状态为准。

左侧四图布局按相机角色排列，并显示序列号和点数；右侧含角色文件、四路质量汇总、完整性检查及候选应用信息。使用“全部适应”“全部1:1”统一调整显示，“隐藏数据/显示数据”切换数据面板。

11.1 四角校正流程与应用

  1. 后端可用且四个理论点文件均校验通过后，点击“四路采集”，取得一次完整四相机图像。
  2. 点击“检测圆心”，逐相机检查是否识别完整网格。
  3. 在每台相机图中分别指定 P1、P2。四组方向应对应同一物理坐标约定，不按图像显示方向直接推断物理方向。
  4. 点击“计算四矩阵”，得到每个角色的候选变换。
  5. 点击“质量验证”，查看四路检测点数、RMS、最大残差和质量结果；检查角色文件、角色/序列号、坐标方向与候选完整性。
  6. 四路均通过后点击“原子应用”，一起更新四份标定文件并重新建立运行时。
  7. 成功后检查视觉就绪；任一路失败时，不允许仅应用其余三路。需要放弃本次维护时点击“重置”。

文件保存与失败处理

校正目标文件由算法主配置的 calibration 节点确定。应用时保留原文件中的图像尺寸、相机内参、畸变及新内参，只替换 image_to_physical。候选与备份在原文件同目录产生，随后执行校验、替换与运行时重建。

可捕获失败时程序尝试恢复原文件和旧运行时；恢复失败会使视觉服务进入故障状态，需维护人员检查文件及诊断。本阶段没有断电或进程崩溃恢复日志保证，应用过程中保持电源稳定，重要标定应另行备份。

校正与生产的区别

校正采集用于维护，不调用生产定位算法，也不会形成生产 OK/NG 位姿。修改已应用标定前应保留原配置和对应设备信息，避免把不同角色或不同镜头条件下的标定交叉使用。

12 理论点文件格式与示例

理论点为 UTF-8 文本，严格两列 X,Y，单位为毫米。每个非空行是一个点，文件行顺序即 P1～PN；无表头、注释或额外列。允许 BOM、空白和空行。数值须有限、点互不重复且整体非共线。文件名及扩展名不用于推断角色。

网格边长 n 支持3～15，点数为 n²；当前示例 n=5，必须提供25个点。四角相机四份文件点数须一致，各自按相机角色独立绑定，并使用统一加工坐标系。物理编号从左下角 P1 开始，每行沿 +X、各行沿 +Y。

常见输入错误

带“X,Y”表头、三列坐标、NaN/Inf、重复点、数量不是完整方阵、四角文件点数不一致、行顺序与 P1/P2 方向不一致，都需要修正。表格软件另存文件时确认使用英文逗号和数值格式。

13 配置编辑、撤销与保存

  1. 进入任一配置页并修改参数。底部显示未应用修改数量及类别；当前运行配置尚未改变。
  2. 不保留修改时点击“撤销修改”，恢复当前已应用配置。
  3. 保留修改时确认任务空闲、无标定维护占用，点击“应用并保存”。
  4. 在确认框选择 Yes 继续，选择 No 返回草稿。设备或 TCP 可能短暂重启。

截图将演示配置 ACK 间隔由1000改为999 ms，仅用于显示编辑与保存过程，不是推荐生产值。运行配置变更按受控流程生效；失败时查看提示和诊断，程序尝试恢复原配置。

相机、光源和算法相关变更会重新创建视觉运行时；TCP 变更会断开当前客户端并重新监听。生产任务开始后不能以编辑配置来取消定位。

13.1 配置保存结果与文件维护

  1. 确认底部回到“配置已同步”，修订号增加，应用和视觉处于可用状态。
  2. 在“通信与系统 → 日志与系统”核对正在使用的配置路径和运行后端。
  3. 对设备配置、算法主文件、所有参数、标定及模板资源进行配套备份。
  4. 需要恢复历史配置时，使用配套文件重新加载；界面“撤销修改”只能撤销尚未应用的草稿，不能回滚已保存版本。

配置由应用保存到启动 --config 指定的文件，不是任意另存文件。应用 JSON 保存使用受控文件写入，路径会按文件位置处理。不要在运行时同时用外部编辑器覆盖应用正在保存的同一个 JSON。

单纯修改同一路径下的算法 YAML 不会自动触发在线重载。通过切换已准备好的主配置路径或安全重启加载文件修改。生产参数应先备份，再在维护空闲期修改和核验。

14 TCP 连接设置

  1. 进入“通信与系统 → TCP”。
  2. 填写监听地址、端口、心跳超时和最大报文，确认与上位机一致。
  3. 点击“应用并保存”，确认后等待重新监听；客户端按新地址重新建立连接。
参数仓库示例 / 使用说明
监听地址真实示例为0.0.0.0，表示绑定本机可用接口；模拟示例为127.0.0.1，仅本机联调。客户端应连接实际主机IP。
端口仓库示例9000，可选1～65535；不得与其他服务冲突。
心跳超时示例3000 ms；上位机通常每秒发送一次 heartbeat，超时关闭连接。
最大报文示例16384 bytes，单条 UTF-8 JSON 换行报文的大小限制；UI下限256 bytes。

同一时刻只允许一个客户端。第二客户端被拒绝；断线不会取消已开始的定位。原连接断开后，旧任务结果不会补发给新连接。网络防火墙应允许实际使用的程序和监听端口。

15 结果确认与重发

  1. 进入“通信与系统 → 结果确认”。
  2. 设置 ACK 间隔和最大重试次数，应用并保存。
  3. 上位机对每次最终 OK、NG、ERROR 都发送同 taskId 的 resultAck；根据任务ID去重，避免重复执行后续设备动作。
参数 / 行为说明
ACK 间隔仓库示例1000 ms；决定等待结果确认和再次发送的间隔。
最大重试次数仓库示例3，界面允许0～100；具体值按上位机处理时间和通信策略确定。
重发内容只重发已确定的网络结果，不重新采集或重新运行定位算法。
等待确认属于结果交付阶段，界面任务可能显示等待确认；新定位仍受忙状态限制。
断线新连接不接管旧连接在途任务，可查询当前状态后决定下一步。

结果ACK与心跳是不同报文。收到定位结果并发送ACK后，仍需持续发送 heartbeat 维持连接。重试耗尽时查看诊断和上位机收包记录，不应把已完成定位误判为算法未执行。

19.1 算法主配置与启用条件

%YAML:1.0
---
timeout_ms: 500
enabled_algorithms:
  edge: 1
  mark: 0
calibration:
  parameters: "parameters/calibration.example.yaml"
  center: "calibration/center.example.yaml"
  top_left: "calibration/top_left.example.yaml"
  top_right: "calibration/top_right.example.yaml"

  bottom_left: "calibration/bottom_left.example.yaml"

  parameters: "parameters/edge.example.yaml"

  parameters: "parameters/mark_point.example.yaml"

timeout_ms 示例500 ms，是一次生产算法调用的协作式预算；MarkPoint 四图识别与融合共享这一预算。算法在主要阶段边界检查超时，不能把500 ms理解为整个Locate或函数返回时间的硬上限。采图和光源不消耗此算法预算。

edge/mark 为0或1的启用标记，按实际模式准备资源。启用Mark时需有效四角参数、标定和模板；对未启用算法发起任务会失败，不能只依靠TCP接受模式字符串判断资源已准备完成。

配置主文件可以引用不同目录的资源，所有相对引用按引用所在文件定位。拷贝一个完整配套目录比单独拷贝某个矩阵或模板更便于维护与恢复。

模板匹配本身的建模角度范围、尺度、相似度等部分参数固定在当前代码中，未开放为生产YAML字段；不要添加看似合理但程序未读取的配置字段。当前UI不提供模板训练按钮。模型应由配套离线流程提供，和匹配器版本、类别、原图尺寸及特征参数一致。

四角标定应输出统一物理坐标，才能把四点平均为设备位姿。示例mark=0时不代表已具备生产模板；启用前应完成资源准备与真实工件验证。

20 TCP 报文与上位机联调

传输为TCP长连接，每条消息是UTF-8紧凑JSON对象，以换行符 LF（\n）结束，version固定为1。不可省略换行；一次接收可能包含半条或多条消息，客户端也需正确组包。

客户端命令字段与用途
prepareLocatetaskId 为1～20位非零十进制字符串；mode为EDGE或MARK_POINT；申请定位。
resultAcktaskId与最终结果一致；确认OK、NG或ERROR。
heartbeatsequence为uint32；建议每秒发送一次，返回heartbeatAck。
queryStatussequence为uint32；查询应用/视觉/任务状态，返回statusReply，忙时可使用。
recoversequence为uint32；申请视觉恢复，返回recoverResult，受当前状态约束。
服务端消息含义
locatePrepared目标相机已准备采集，真实外部触发由设备系统按约定提供。
prepareRejected当前不能接受任务，例如Busy或NotReady；不要等待定位结果。
locateResult最终OK、NG或ERROR。OK/NG携带坐标，ERROR携带errorCode和message。
protocolError协议版本、格式、字段或消息大小错误；部分错误会导致断开。

taskId示例使用"1002"，保持为JSON字符串。mode在界面显示为Edge/MarkPoint，在网络中使用大写EDGE/MARK_POINT。没有CancelCommand，也没有通过断线取消定位的机制。

20.1 报文示例与联调顺序

心跳与状态查询

{"version":1,"type":"heartbeat","sequence":1}
{"version":1,"type":"queryStatus","sequence":2}

Edge 请求与最终结果示例

{"version":1,"type":"prepareLocate","taskId":"1002","mode":"EDGE"}
{"version":1,"type":"locatePrepared","taskId":"1002","mode":"EDGE"}
{"version":1,"type":"locateResult","taskId":"1002","mode":"EDGE","outcome":"OK","x":12.5,"y":-3.2,"r":1.25}
{"version":1,"type":"resultAck","taskId":"1002"}

NG、错误与恢复

{"version":1,"type":"locateResult","taskId":"1003","mode":"MARK_POINT","outcome":"NG","x":0.0,"y":0.0,"r":0.0}
{"version":1,"type":"locateResult","taskId":"1001","mode":"EDGE","outcome":"ERROR","errorCode":"HARDWARE_FAILURE","message":"The simulated camera capture failed."}
{"version":1,"type":"recover","sequence":3}

上述多行依次演示消息，发送方向依type区分；每条实际发送时应为单行JSON并追加换行。ERROR与NG同样需要resultAck。ERROR示例为本次模拟注入故障的真实报文。

已有联调脚本

.\tools\demo_tcp_client.ps1 -ServerAddress 127.0.0.1 -ServerPort 9000

脚本应配合仓库默认模拟配置运行，用于状态、首次故障与恢复、忙状态、Edge OK、MarkPoint NG、心跳和确认流程联调。若使用本次文档独立实例，端口改为19090；首次故障已消耗的实例应重新启动再运行脚本。该脚本不是操作界面功能。

21 安全退出与日常维护

  1. 停止上位机发送新的生产定位请求。
  2. 通过“文件 → 退出”或窗口关闭按钮退出。
  3. 若有未应用配置，阅读提示：Yes 放弃草稿并关闭，No 返回窗口继续编辑或保存。
  4. 在途任务继续自然执行；软件关闭硬件与视觉资源后退出。不要把等待关闭误认为可强制中止当前任务。

维护与备份

定期配套备份应用JSON、算法主文件、参数、五台相机标定及模型资源，并记录适用设备和日期。更换镜头、相机、安装位置或光学条件后，应重新评估标定与定位参数。日志按容量轮转，重要故障记录应在轮转前另行保存。

软件没有单独的任务取消按钮，不在主线程同步等待视觉任务；退出期间界面可能短时保持关闭中状态。算法预算是协作式检查，实际返回可能晚于预算；硬件操作使用各自有限等待。
